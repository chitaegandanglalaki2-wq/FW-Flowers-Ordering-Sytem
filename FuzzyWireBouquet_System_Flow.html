1. What the system already does

Two portals: customer shop and a separate admin login. Catalog orders go through cart, checkout, payment, status timeline, and a simulated delivery map. Custom bouquets are submitted as requests (materials + photo or drawing) and join the same FIFO work queue, but they do not use checkout, GCash, address, time slot, or live tracking.

6. Features to add

# Feature Area Why
1 Manual GCash QR proof review Payment Customer uploads an image after paying in GCash; an admin must review it before the payment is marked Paid.
2 Custom-order checkout Fulfillment After quote accept, reuse address, slot, voucher, COD/GCash, and map tracking.
3 Quote accept / revise Custom Admin can change price or materials; customer accepts before production.
4 Map-based delivery fee Delivery Compute km from shop and delivery geocodes. Do not trust typed distance.
5 Reserve custom materials Inventory Hold or deduct stock on Confirm; restore on Cancel.
6 Customer cancel / reschedule Orders Allow cancel or slot change while status is still Pending.
7 Order emails Comms Reuse existing SMTP (password reset) for confirm, out-for-delivery, and cancel.
8 Product cost / profit Analytics Store cost per bouquet and material so analytics can show profit.
9 Proof of delivery Delivery Photo when marking Delivered, plus existing customer receipt confirm.
10 Occasion calendar Shop Lead-time warnings for Valentine, Mother’s Day, graduation, and similar dates.

7. What to improve

Change Area Current gap
Split app.py Architecture One large file holds routes, schema bootstrap, payments, maps, and chat.
Replace visit-time migrations Data Schema is patched when a page is opened. Use schema.sql plus a migration folder.
FIFO account approval UX Oldest pending registration must be decided first. Allow skip with a logged reason for a real shop.
Pickup geocode Maps Shop address is not Nominatim-friendly, so the map route stays empty.
Pickup statuses Orders Use Ready for Pickup / Picked Up instead of Out for Delivery.
Custom payment states Payment custom_orders.payment_status is only Unpaid or Paid. Align with Pending, Failed, Refunded.
Label the map honestly Tracking Call it Estimated route. Do not imply live GPS.
Automated tests Quality Cover checkout totals, voucher once-per-customer, slot capacity, FIFO queue, and stock decrement.

8. Suggested build order

  1. A — Payment and distance: GCash QR plus proof upload/admin review, honest payment states, geocoded delivery fees, searchable shop address.
  2. B — Unify custom orders: quote → checkout reuse → reserve materials.
  3. C — Polish: customer cancel, order emails, proof of delivery, cost/profit, then split app.py and add tests.

Out of scope unless the paper needs it: live rider GPS, guest checkout, multi-branch inventory, native app.
